# AI Opportunity Scorecard

This scorecard helps prioritize where AI or automation is most likely to create meaningful operating leverage.

Score each dimension from **1 (low)** to **5 (high)**.

| Dimension | Question | Score |
|---|---|---:|
| Business Impact | If improved, how much does this matter to revenue, cost, risk, capacity, or customer experience? | |
| Volume | How frequently does the work occur? | |
| Repeatability | Are the inputs, decisions, and outputs consistent enough to standardize? | |
| Data Availability | Is the information needed to perform the work available and usable? | |
| AI Suitability | Does the work involve classification, extraction, summarization, drafting, pattern recognition, or bounded reasoning? | |
| Implementation Feasibility | Can an MVP be built and tested without major system changes? | |
| Adoption Readiness | Are users and workflow owners likely to adopt the change? | |
| Risk Manageability | Can errors be detected, reviewed, and contained? | |

## Interpretation

**High-priority candidate**
- strong business impact
- high volume
- repeatable workflow
- manageable risk
- clear human owner
- measurable baseline

**Proceed carefully**
- ambiguous success criteria
- weak data quality
- high exception rates
- unclear ownership
- significant compliance or customer-impact risk

**Poor automation candidate**
- low volume
- highly bespoke work
- no measurable outcome
- automation cost exceeds likely benefit
- errors cannot be reliably detected

## Decision Rule

The highest-scoring workflow is not automatically the best first project.

A good first AI project should also:
1. produce visible value quickly,
2. be reversible,
3. have an engaged workflow owner,
4. create learning that transfers to other processes.

## Portfolio View

Use the scorecard to create three buckets:

- **Now:** high value, feasible, low-to-moderate risk
- **Next:** attractive but requires data, integration, or process cleanup
- **Not Yet:** unclear value, high risk, or weak operating foundation

The purpose is disciplined prioritization, not maximizing the number of AI projects.
